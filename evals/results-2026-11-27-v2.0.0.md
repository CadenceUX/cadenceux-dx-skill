# Eval results: cadenceux-developer-experience 2.0.0 (reworked), 2026-11-27

Baseline: the released `cadenceux-dx` 1.0.2, snapshot from the `v1.0.2` tag, on Sonnet, launched
before any skill edit. Each run: a fresh subagent with the skill folder only (no `evals/`,
`docs/`, CHANGELOG, README or plugin manifest), text only, nothing run, ADK available, stack
check taken as already run, the Skill tool not used. Models, as each run reported them:
`claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`. Graded against `must` and
`must_not` by a separate Opus grader that quoted evidence for every item; failures were read
by hand. Gradings and answers were kept in the session's scratch folder, not in the repo.

✅ every must met, no must_not hit. ⚠️ one must partly met or missing, gist right. ❌ otherwise.

## Changes made after the first run

1. **Stage order and the Blue hat** (twelve-hats): SKILL.md now says to give the six stages in
   order, then deploy, with the Orchestrator across them as the Blue hat, whenever the model or
   the Developer's time is explained; `working-agentically.md`'s Orchestrator row names the Blue
   hat and "from the stage that owns the problem".
2. **Reading the log first** (sprint-update): the sprint log template starts with the line
   "Every sprint starts by reading the needs brief, the sprint plan and this log", and SKILL.md
   says to put it at the top of the log and in the hand-back.
3. **The three solo rules together** (solo-review): SKILL.md gives change hats, write the
   hand-back and never review your own build as one set, to be given together.
4. **Standard practice behind the gates** (standard-or-ours): listed in `sprints-and-hats.md`
   itself instead of a pointer to `stage-gates.md`, which models didn't follow.
5. **Build review versus system review** (webviewer-review): SKILL.md says reviewing what the
   Agent just built is review and optimise, not a review of an existing system, so it starts
   straight away.

Each fix was rerun on the affected cases only. The other cases ran on the copy before these
fixes; the fixes only add lines, so a regression there is unlikely but not tested.

## Cost

Tokens per run (mean): 1.0.2 baseline 70k; reworked 2.0.0 Haiku 81k, Sonnet 76k, Opus 81k
(range 69k to 89k). The 2.0.0 first draft measured 74k. Time per run 11 to 75 seconds; Opus
slowest. 94 answer runs, about 7.3 million tokens, plus six grader runs of about 95k each.

- The skill installed and used in a real session.
- Regression cases on Opus; the earlier regression cases (routing, stack check, data access,
